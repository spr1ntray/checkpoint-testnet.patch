# Руководство пользователя Soft Hub

Soft Hub — локальное приложение для запуска и наблюдения за вашими софтами автоматизации. Оно устанавливается из DMG, хранит общую базу профилей и показывает журнал, прогресс и результаты в одном окне.

Это руководство предназначено пользователю приложения. Python, Node.js, npm, терминал и исходники для обычной работы не нужны.

## 1. Поддерживаемая сборка

Текущий пользовательский preview — **Soft Hub 0.6.4**:

- macOS;
- Mac с Apple Silicon (`arm64`);
- артефакт `Soft Hub-<version>-arm64.dmg`;
- собственный управляемый Python runtime внутри приложения.

Intel Mac текущим DMG не поддерживается.

## 2. Установка

1. Получите DMG из доверенного источника.
2. Сверьте SHA-256 файла со значением, опубликованным вместе с артефактом.
3. Откройте DMG.
4. Перетащите **Soft Hub** в **Applications**.
5. Извлеките DMG.
6. Откройте **Soft Hub** из Applications обычным кликом.

Приложение не использует установленный в системе Python. Если встроенный runtime отсутствует или повреждён, Soft Hub покажет ошибку и попросит переустановить приложение.

### Gatekeeper в текущем preview

Локальный preview подписан ad-hoc и не notarized Apple. Gatekeeper может заблокировать первое открытие.

Если вы сами собрали приложение или получили файл по доверенному каналу и сверили SHA-256, используйте штатное подтверждение macOS в **System Settings → Privacy & Security → Open Anyway**. Не отключайте Gatekeeper глобально и не удаляйте quarantine-атрибут командами.

Публичный релиз должен быть подписан сертификатом Developer ID Application и пройти Apple notarization. До этого текущий DMG следует считать локальным preview, а не публичным production-инсталлятором.

## 3. Первый запуск и Vault

При первом запуске приложение предложит создать Vault.

1. Придумайте мастер-пароль длиной не менее 14 символов.
2. Используйте уникальный пароль, которого нет у почты, кошелька или других программ.
3. Сохраните пароль в надёжном password manager.

Мастер-пароль не записывается в БД. В текущем MVP нет recovery key и сброса забытого пароля. Потеря пароля означает потерю доступа к зашифрованным данным Vault.

Vault остаётся разблокированным до ручной блокировки, завершения приложения либо системного lock-screen/suspend. После возвращения desktop-версия перечитает состояние и попросит разблокировать хранилище снова. Это не может отозвать секрет, уже переданный работающему plugin process, поэтому всё равно завершайте ненужные задачи.

При ручной блокировке UI сразу закрывает журналы, модальные окна и панель Operations, очищает client cache аккаунтов, runs, account states, results и events и отбрасывает запоздавшие ответы, начатые до lock. API в закрытом состоянии не возвращает эти проекции и не даёт скачать журнал. Доступными остаются только безопасные агрегатные счётчики активных и требующих внимания операций — они не раскрывают название софта, аккаунт или текст ошибки. Уже запущенный process при этом не останавливается автоматически.

Важно: Vault — это зашифрованное хранилище, а профиль — отдельная импортированная строка аккаунта. Создание или разблокировка Vault не создаёт wallet, proxy или email и не означает, что профиль уже готов к запуску. Новый Vault может быть открыт и при этом содержать `0 профилей`; связку можно импортировать в разделе **Аккаунты** или кнопкой **Добавить аккаунты** прямо из окна запуска.

## 4. Импорт профилей

Soft Hub импортирует строгие связки 1:1. Основной режим принимает таблицу из ровно пяти колонок:

1. `private_key` — EVM private key из 64 hex-символов, с `0x` или без него;
2. `proxy` — HTTP proxy в формате `host:port:user:password` или `http://user:password@host:port`;
3. `email`;
4. `twitter` — значение можно оставить пустым;
5. `adspower_profile` — AdsPower profile ID; значение можно оставить пустым. В табличном режиме обе опциональные колонки всё равно должны присутствовать.

Таблицу можно:

- вставить прямо из Excel или Google Sheets;
- загрузить как CSV, TSV или TXT с разделителем tab, `;` или `,`;
- включить первую строку-заголовок `private_key,proxy,email,twitter,adspower_profile`.

В ручном режиме поля вводятся отдельными построчными списками. Первые три списка обязательны и должны иметь одинаковую длину; Twitter и AdsPower можно не заполнять, но длина заполненного списка тоже должна совпасть.

Email password и label необязательны. Если дополнительный список заполнен, число строк должно совпадать с числом private keys.

Перед импортом проверьте порядок строк: первая строка каждого списка станет одним профилем, вторая — следующим и так далее. При любой ошибке импорт целиком откатывается; частично записанных профилей не будет.

Если private key уже есть в Vault, повторный импорт обновляет его account-поля, но сохраняет уже настроенные собственный реферальный код и связь с реферером. Удаление профиля удаляет его секреты; если он был реферером, Hub в той же транзакции снимает связь у его прямых рефералов.

В интерфейс не возвращаются email password, Twitter credential и AdsPower profile ID: Hub показывает только флаги `email_password_configured`, `twitter_configured` и `adspower_configured`. Сами значения шифруются в account bundle и выдаются только плагину с exact action grant. Не вставляйте секреты в скриншоты, issue, чат, обычные заметки или журнал запуска.

### Глобальные Capsolver и AdsPower API keys

По одному глобальному ключу хранится на весь Hub, а не на каждый аккаунт. Capsolver API key задаётся в **Настройках**, AdsPower Local API key — в **Аккаунтах** в блоке **AdsPower Local API** над таблицей. Они шифруются в Vault отдельно от account bundles; при открытом Vault UI возвращает только status-only флаги `capsolver_configured` и `adspower_api_configured`, но не сами ключи. При закрытом Vault даже configured-статус скрыт. Каждое значение получает только выбранное action с exact grant.

Для browser-софта укажите отдельный AdsPower profile ID у каждого нужного аккаунта и один общий AdsPower API key в блоке над таблицей аккаунтов. Hub хранит и выборочно выдаёт эти значения, проверяет их наличие и запускает subprocess. Он не устанавливает AdsPower, Chrome, browser driver или Playwright browser, не запускает AdsPower за пользователя и не сандбоксит его сеть/ОС. Внешняя среда должна быть заранее установлена и запущена, а плагин сам отвечает за актуальный endpoint/auth и cleanup browser session.

### Реферальная сеть

В **Аккаунтах** нажмите **Настроить цепочку**. Для каждого профиля доступны три режима пригласившего: **без реферера**, **другой аккаунт Hub** или **внешний код**. Там же можно задать собственный код профиля — его получат те аккаунты, которым он назначен реферером.

Hub показывает цепочки по label, но никогда не возвращает ранее сохранённые коды в поля UI: пустое поле означает «оставить текущий», новое значение — «заменить», а **Удалить** — «очистить». Предпросмотр сразу покажет цикл; backend повторно проверит всю сеть и сохранит bulk-edit одной транзакцией. При ошибке ни одна строка не изменится.

Текущий встроенный Umia `1.0.2` не объявляет это permission и не реализует CAPTCHA/Privy flow. Даже при заданном Capsolver key его faucet и auto-registration остаются заблокированными; для swap/bids нужны заранее пополненные Base Sepolia ETH и mUSDC.

### Plaintext export: XLSX или raw CSV

В **Аккаунты** кнопка **Экспорт** доступна только при открытом Vault и непустой базе. Перед скачиванием Hub требует:

1. Повторно ввести мастер-пароль.
2. Точно, с тем же регистром и пробелами, ввести `EXPORT PLAINTEXT SECRETS`.

Рекомендуемый файл `soft-hub-accounts.xlsx` содержит `private_key,proxy,email,twitter,adspower_profile` как точные строковые значения. Даже если ячейка начинается с `=`, `+`, `-` или `@`, Excel не исполнит её как формулу. Для автоматического импорта можно явно выбрать `Raw CSV`: он сохраняет исходные значения, но его нельзя открывать в Excel/Google Sheets. Ни один формат не содержит email passwords, labels/tags, собственные/внешние реферальные коды, связи между Hub-аккаунтами или глобальные Capsolver/AdsPower API keys. Это не backup Vault: после download файл хранит включённые account secrets в открытом виде, но не сможет восстановить исключённую реферальную сеть. Переместите его в зашифрованное хранилище или удалите сразу после использования.

### Пульт операций

Нижняя панель не дублирует левое меню. Она показывает только текущую операционную работу:

- сколько задач сейчас работает или ждёт сверки;
- сколько софтов отмечено для пачки;
- запуск выбранной пачки;
- переход ко всем активным либо требующим внимания задачам.

## 5. Установка софта

Soft Hub принимает полные versioned packages с расширением `.softhub`, `.softhub.zip` или `.zip`. В разделе **Патчи** есть четыре канала:

- **Из Hub** — готовые адаптеры, уже включённые в desktop-сборку;
- **Local package** — файл с диска или drag-and-drop;
- **Patch Radar** — лента public repositories владельца с точным case-insensitive суффиксом `.patch`;
- **GitHub Release** — HTTPS-ссылка на public repository, `releases/latest`, `releases/tag/<tag>` или прямой release asset.

1. Получите пакет и его hash из доверенного источника либо выберите встроенный пакет.
2. Откройте раздел **Патчи**.
3. Выберите карточку из Hub/Patch Radar, перетащите файл или вставьте GitHub URL.
4. Проверьте имя, полное описание, icon/cover, версию, запрошенные секреты, domains, chains и уровень риска. Новый 0.6-пакет обязан сам приносить эти presentation-данные; без них допустимы только legacy-пакеты.
5. Если состояние модуля — `needs_setup`, нажмите **Подготовить**.
6. После подготовки запустите read/self-check действие.

Если встроенный адаптер новее установленного, карточка получает статус **UPDATE** и кнопку **Обновить до v…**; badge раздела **Патчи** учитывает такие обновления. Hub не подменяет код молча: обновление остаётся явным действием, а более новая локальная версия не понижается встроенным пакетом.

В нижней строке каждой карточки есть три компактных управляющих кнопки:

- знак **питания** — включить или выключить новые запуски софта;
- знак **истории со стрелкой** между питанием и корзиной — rollback к другой ранее установленной версии;
- **корзина** — удалить код и окружение софта с сохранением audit history/results.

Каждая кнопка показывает двухстрочную подсказку при наведении или keyboard focus. Rollback не исчезает, если откатываться некуда: он помечается недоступным, а подсказка и нажатие сообщают: **«Предыдущей установленной версии пока нет»**. Перед рабочим rollback Hub показывает подтверждение.

Команда **Подготовить** автоматически создаёт отдельное окружение модуля. Пользователь не устанавливает Python вручную, но загрузка зависимостей может требовать интернет.

Пакеты сейчас имеют статус `local_unsigned`. Внутренние SHA-256 проверяют целостность архива, но не личность автора. Подготовка dependencies и запуск плагина выполняют сторонний код с правами текущего пользователя. Устанавливайте только собственные или полностью проверенные пакеты.

Patch Radar принимает GitHub username или URL вида `https://github.com/<owner>`, запоминает нормализованный owner в локальных settings и сканирует не более 100 public repositories. Имя должно точно заканчиваться на `.patch` без учёта регистра: `wallet.PATCH` подходит, `wallet.patch.zip` — нет. Для каждого repository берётся только latest release; к установке допускается release с ровно одним asset, имя которого заканчивается на `.softhub` или `.softhub.zip` без учёта регистра. Metadata этого asset также должна содержать целый `size` от 1 byte до 256 MB и `browser_download_url` длиной не более 2048 символов. Нет release, нет asset или подходящих assets не ровно один — карточка остаётся неустанавливаемой.

GitHub-установка не делает пакет доверенным: repository может быть чужим, а release asset — подменённым автором. Hub 0.6.4 работает только с public GitHub Releases, не принимает tokens/credentials в URL, независимо ограничивает фактический download 256 MB и не идёт по redirect на произвольный host. Patch Radar тоже работает без GitHub Authorization, поэтому private repositories и превышение анонимного rate limit не обходит. После скачивания действуют те же manifest/checksum/архивные проверки, что и для локального файла.

## 6. Запуск действий

В разделе **Софты** выберите модуль и действие.

- `read` — чтение без финансовой транзакции;
- `external_write` — non-financial изменение внешнего сервиса без blockchain-транзакции и финансового подтверждения;
- `testnet_write` — действие в testnet с одним checkbox подтверждения от Hub; API при этом проверяет точное acknowledgement `TESTNET`;
- `mainnet_write` — mainnet-действие с точной фразой подтверждения из манифеста.

Для account-действия run modal ведёт себя так:

- если импортирован ровно один профиль, он выбран автоматически;
- если профилей нет, вместо пустого списка показано объяснение и inline-кнопка **Добавить аккаунты**; после успешного импорта Hub вернёт вас к тому же модулю и действию;
- если профилей несколько, отметьте нужные строки явно или нажмите **Выбрать все**; при смене действия прежний multi-profile выбор сбрасывается, чтобы batch одного сценария не переносился в другой;
- если профили есть, но для `one_or_more` не выбрана ни одна строка, форма показывает inline-ошибку и переводит внимание к селектору.

Поля `integer` принимают целые значения с шагом 1. Поля `number` поддерживают дробные значения: шаг берётся из положительного `multipleOf` манифеста, а без него разрешён произвольный дробный шаг. Пустое необязательное числовое поле не отправляется как `0` или `null`.

Для `testnet_write` подтверждение в окне всегда одно — Hub-owned checkbox. Служебная option `acknowledge_testnet_transactions` отдельно не показывается: после checkbox Hub сам проверяет `TESTNET` и передаёт `true` историческому адаптеру, только если тот объявил это boolean-поле в schema. Не запускайте один wallet одновременно в legacy CLI и Hub: внешний процесс не участвует в leases Hub.

`external_write` — отдельная non-financial категория для действий вроде регистрации в waitlist. Она меняет состояние внешнего сервиса, поэтому не обозначается как read-only: после принудительной остановки неоднозначный результат попадёт в `needs_attention`. Такое действие разрешено в пачке и помечается в preflight как **Внешняя запись**.

Сначала используйте один тестовый профиль и минимальные суммы. Перед write-действием независимо проверьте chain ID, RPC, адреса контрактов, balance, allowance и лимиты.

### Проверка ресурсов до запуска

Новый софт объявляет необходимые данные отдельно для каждого действия через `actions[].resources`. Hub проверяет их до создания plugin process и сразу показывает понятную причину блокировки:

- account resources: private key, proxy, email, email password, Twitter, AdsPower profile ID, собственный referral code или эффективный код реферера у каждого выбранного профиля;
- global settings: Capsolver API key и AdsPower API key; первый задаётся в **Настройках**, второй — в блоке AdsPower раздела **Аккаунты**.

Если ресурса не хватает хотя бы одному выбранному аккаунту, одиночный или пакетный запуск не начинается. Добавьте account-данные, реферальную связь или AdsPower key в **Аккаунтах**, либо Capsolver key в **Настройках**, затем повторите preflight. Открывать технический журнал, чтобы узнать о пустом поле, не требуется. Legacy-пакет без `resources` может не дать такого раннего объяснения; все новые пакеты 0.6 обязаны следовать [строгому ТЗ](SOFTWARE_SPEC_RU.md).

### Запуск нескольких софтов пачкой

1. В разделе **Софты** отметьте галочками нужные карточки либо нажмите **Выбрать готовые**.
2. Нажмите **Запустить выбранные** на панели над карточками или кнопку пачки в нижнем пульте.
3. В preflight выберите action для каждого софта и политику профилей: все или только первый.
4. Один раз подтвердите testnet-действия и нажмите **Запустить параллельно**.

Hub полностью проверяет пачку на backend, запрещает mainnet actions, одной транзакцией создаёт все runs и write-leases и затем выполняет до четырёх задач одновременно. Если один элемент не прошёл проверку или конфликтует по lease, не запускается ничего. Повтор после оборвавшегося ответа использует тот же idempotency key и не создаёт дубликаты.

## 7. Активность и результаты

После запуска:

- кнопка **Operations** в нижнем пульте открывает компактную таблицу по всем софтам и аккаунтам: текущий этап, progress, честный lifecycle status и давность обновления;
- **Результаты** хранит структурированные итоги плагина;
- stderr и protocol warnings появляются в журнале запуска;
- **Попросить остановку** доступно плагину, объявившему `safe_stop`;
- **Завершить процесс** доступно для любой активной задачи и требует точную фразу `FORCE STOP`.

Отдельной вкладки «Активность» слева нет. В Operations переключатели **Сейчас** и **Проверить** оставляют рабочую навигацию свободной; явные кнопки справа в строке открывают немодальные детали запуска и переводят фокус к штатным кнопкам остановки. Таблица берёт итог аккаунта только из типизированного `account_state`, а не угадывает его по последней строке терминала. В деталях lifecycle-таблица показывается первой, а сырой технический журнал раскрывается отдельно. Пока один run виден, можно выбирать и запускать другие софты. Остановка процесса не откатывает уже подписанную транзакцию или отправленный POST. После force stop либо сбоя всегда сверяйте внешнее состояние.

В деталях запуска кнопка скачивания сохраняет ограниченный UTF-8 JSONL-журнал. Hub не включает в него manifest/options, повторно очищает события от известных private-key/proxy/email/password/token/header patterns, ограничивает файл `16 MiB` и помечает усечение в footer. Это дополнительная защита, а не гарантия DLP: софт по контракту вообще не имеет права отправлять секрет в log, result, exception, URL, screenshot или файл. Перед передачей журнала третьему лицу всё равно просмотрите его вручную.

При закрытом Vault вкладка **Результаты**, строки Operations, детали run, events и скачиваемый журнал недоступны. Ни старый client cache, ни запоздавший HTTP-ответ не должны вернуть их на экран до следующей успешной разблокировки. Нижний пульт может показывать лишь общее число активных/требующих внимания задач без их имён и деталей.

Задачу, которая ещё стоит в очереди и не запустила subprocess, можно остановить сразу: она завершится как **Остановлено**, не получит доступ к secrets и освободит заранее зарезервированный write-lease. Если процесс уже стартовал, для write-действия сохраняется консервативное правило внешней сверки.

### Удаление софта

Кнопка корзины на карточке удаляет код, все версии и `.venv`. История запусков и результаты сохраняются. Hub не удалит модуль, пока у него есть queued/running/cancelling либо `needs_attention` run: сначала остановите задачу, проверьте внешний итог и выполните сверку.

### Статус «Нужно внимание»

`needs_attention` означает, что write-run завершился неоднозначно: Hub не может доказать ни успех, ни отсутствие внешнего side effect.

1. Не нажимайте retry сразу.
2. Проверьте nonce, receipt, transaction hash, orders и позиции в независимом explorer/API.
3. Зафиксируйте фактический итог.
4. Только после сверки нажмите **Сверка выполнена** и введите `RECONCILED`.

До сверки Hub удерживает account leases, чтобы случайный повтор не удвоил операцию.

### Обычная известная ошибка

Статус **Ошибка** отличается от **Нужно внимание**: процесс закончил работу с известным неуспешным результатом, защитного lease уже нет и повторный запуск не заблокирован. Сначала откройте общий лог софта, затем нажмите **Ошибка просмотрена**. Hub уберёт запись из живых оповещений и покажет статус **Просмотрено**, но сохранит исходную ошибку, состояния аккаунтов, results и полный очищенный журнал в истории. Вводить `RECONCILED` для обычной ошибки не нужно.

## 8. Где хранятся данные

Пользовательские данные находятся отдельно от приложения:

```text
~/Library/Application Support/Soft Hub
```

Там находятся:

- `hub.sqlite3` и временные WAL-файлы;
- зашифрованные account bundles, включая Twitter, AdsPower profile ID, реферальные коды/связи, глобальные Vault secrets вроде Capsolver/AdsPower API keys и публичные metadata профилей;
- установленные версии плагинов и их окружения;
- журналы, results и run scratch;
- lock текущего экземпляра.

Каталог **Soft Hub.app** внутри Applications не содержит пользовательский Vault. Поэтому замена приложения новой версией не удаляет профили, плагины, историю и результаты.

## 9. Обновление приложения

В MVP нет автоматического updater.

1. Завершите активные runs либо доведите неоднозначные writes до внешней сверки.
2. Заблокируйте Vault.
3. Полностью завершите Soft Hub.
4. Сделайте backup data directory.
5. Получите и проверьте новый DMG.
6. Перетащите новую **Soft Hub.app** в Applications и подтвердите замену старой.
7. Запустите приложение и проверьте версии, Vault, модули и последний журнал.

Если после обновления модуль перешёл в `needs_setup`, его данные не потеряны: новый managed runtime изменил fingerprint окружения. Нажмите **Подготовить**, чтобы Hub пересоздал совместимую `.venv` этого модуля.

Не переносите файлы из старого `.app` вручную. Runtime и core обновляются единым app bundle, а пользовательские данные остаются в Application Support.

## 10. Backup и восстановление

Встроенного зашифрованного backup/restore пока нет. Plaintext XLSX/raw CSV export из раздела **Аккаунты** — это перенос пяти колонок секретов, а не копия всего Vault, истории, плагинов, глобальных API keys или реферальной сети.

Для согласованной копии:

1. Остановите runs.
2. Заблокируйте Vault.
3. Завершите Soft Hub.
4. В Finder выберите **Go → Go to Folder…** и откройте `~/Library/Application Support/Soft Hub`.
5. Скопируйте весь каталог в зашифрованное хранилище.

Не копируйте только `hub.sqlite3` во время работы: SQLite может использовать `hub.sqlite3-wal` и `hub.sqlite3-shm`. Backup остаётся чувствительным, несмотря на шифрование secret payload.

Для восстановления на совместимой версии приложения полностью завершите Hub и восстановите весь каталог на прежнее место. Проверяйте восстановление на отдельной машине или тестовом OS-профиле до аварии.

## 11. Удаление

Чтобы удалить только приложение, завершите Soft Hub и переместите **Soft Hub.app** из Applications в Trash. Пользовательские данные сохранятся и будут доступны после повторной установки.

Чтобы удалить также Vault, плагины, историю и результаты:

1. Сначала создайте backup, если данные могут понадобиться.
2. Убедитесь, что Soft Hub полностью завершён.
3. Через Finder откройте `~/Library/Application Support/Soft Hub`.
4. Переместите именно каталог **Soft Hub** в Trash.

Удаление data directory необратимо без backup.

## 12. Частые проблемы

### «Встроенный runtime отсутствует или повреждён»

Не устанавливайте системный Python. Завершите приложение, удалите только `.app`, заново скопируйте Soft Hub из проверенного DMG и повторите запуск. Data directory при этом сохранится.

### Приложение блокирует Gatekeeper

Проверьте источник и SHA-256. Для текущего ad-hoc preview используйте только штатный **Open Anyway**. Для неизвестного DMG не обходите блокировку.

### Модуль показывает `needs_setup`

Нажмите **Подготовить** и проверьте доступ к интернету. Если установка зависимостей падает, не запускайте модуль в полуподготовленном состоянии; передайте автору package ID, version и текст безопасной ошибки без secrets.

### Hub сообщает, что data directory уже занят

Обычно уже запущен другой экземпляр приложения. Переключитесь на него или корректно завершите. Не удаляйте lock вручную во время работы процесса.

### Забыт мастер-пароль

Сброса нет. Не перебирайте пароль в production-копии и не удаляйте старый data directory до backup. Для продолжения понадобится новый чистый data directory и уже заменённые credentials.

## 13. Минимальная модель безопасности

- Soft Hub предназначен для одного локального оператора.
- Desktop renderer sandbox не изолирует Python-плагин.
- Разрешённый плагин получает private key в plaintext на время run.
- `permissions.network` и `chains` не являются firewall.
- Checksums плагина не являются подписью автора.
- Ad-hoc подпись preview не заменяет Developer ID и notarization.
- Ценные mainnet-ключи не следует использовать до независимого аудита и отработанного recovery.

Полная модель угроз и incident response: [SECURITY_RU.md](SECURITY_RU.md).
